# Defect classes and their guards

Every fix pull request names one class and the guard that prevents the whole class from coming
back, not only the instance. A defect that fits no class adds a new entry here and, where
possible, a generic automated check.

| Class                                                                          | What went wrong                                                                                               | Guard                                                                                                                                                                                                                                                 |
| ------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **C1** invisible to jsdom: layout, clipping, overlap, scrolling, focus, colour | jsdom performs no layout, so no test saw it                                                                   | Real-render tests only (end-to-end or the design suite); the overlay-integrity check in the page objects (`openMenu`, `openDialog`, `openPopover`); the window-size matrix; the test-level policy in `docs/qa/coverage.md` ("needs real-render test") |
| **C2** state with no way back                                                  | An area could be hidden or closed with no control to restore it                                               | Spec requirement "Hidden areas can always be restored"; persisted-state sweep J-20                                                                                                                                                                    |
| **C3** requirement prose without a scenario                                    | A claim lived in prose, so no test was written                                                                | `pnpm check:spec-completeness` and the spec audit (`docs/qa/spec-audit-prompt.md`) before implementation                                                                                                                                              |
| **C4** design mismatch                                                         | The app drifted from the canvas                                                                               | `design/metrics.json` measured on real boxes; token lint; the side-by-side review (`pnpm qa:design`)                                                                                                                                                  |
| **C5** weak test                                                               | The test passed without observing the behaviour (for example it read a token declaration, not a rendered box) | Test-level policy; the coverage report flags layout scenarios covered only by jsdom                                                                                                                                                                   |
| **C6** fix without a regression test                                           | The fix changed no test                                                                                       | Fix-PR check (`.github/workflows/fix-pr-check.yml`): a changed test or a "No automated test" section with a reason                                                                                                                                    |

## Adding a class

Add a row with the guard, link the defect, and add the generic check (a script, a helper that
every page object calls, or a CI step) in the same pull request when one is possible.
