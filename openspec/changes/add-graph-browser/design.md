## Context

Canvas: `design/canvas/GraphBrowser.dc.html` (schema sidebar, Cypher editor, Graph/Table/JSON/Plan views, graph with label colors and relationship captions, legend, zoom controls, inspector) and the Neo4j form in `design/canvas/ConnectionDialog.dc.html`. The console, results panel, safeguards and AI context builder already exist from earlier changes.

## Goals / Non-Goals

**Goals:** Neo4j Browser-level exploration inside Clew; graph rendering that stays smooth to a few thousand elements; the same safety model as SQL.
**Non-Goals:** other graph databases (Memgraph via Bolt may work but isn't tested; Neptune/ArangoDB not planned), Graph Data Science procedures UI, styling editor (GraSS) beyond caption property and label colors, Bloom-style perspectives.

## Decisions

### Driver
`neo4rs` (async Rust Bolt driver, MIT) was the first choice: supports Bolt 4.x/5.x, routing (`neo4j://`), TLS schemes, and streaming via `RowStream`. Records are converted to the value model with new kinds `node`, `relationship`, `path`; integers stay i64 (and are sent to JS as strings when outside ±2^53). Cancel drops the stream and sends RESET on the connection. Introspection uses `CALL db.labels()`, `db.relationshipTypes()`, `db.propertyKeys()`, `SHOW INDEXES`, `SHOW CONSTRAINTS`, and counts via `MATCH (n:Label) RETURN count(n)` from the count store (cheap). Read-only sessions open transactions with access mode READ.
Alternative considered: HTTP Query API. Rejected: no streaming of large results and no routing.

**Decision at implementation (backend): a small Bolt client instead of `neo4rs`.** Checked against `neo4rs` 0.9.0-rc.10 (June 2026, the newest release): it negotiates Bolt 4.4 at most (no Bolt 5, so no element ids: nodes arrive with a numeric `id` only), routes only behind the `unstable-bolt-protocol-impl-v2` feature, and keeps what the spec needs behind `pub(crate)` fields: the `plan` / `profile` of a result summary (Plan view), and the months / days / nanoseconds of durations, offsets and dates (temporal values). Cancel by dropping the stream would also leave the query running on the server until the pooled connection is next reused. The other crate on crates.io (`neo4j` 0.2, sync only) pulls in `aws-lc-sys` next to the `ring` provider Clew already uses and cannot interrupt a blocked read. So `src-tauri/src/drivers/neo4j/bolt/` implements what Clew needs, with no new dependency beyond `chrono-tz` (time zone offsets for `DateTimeZoneId` values):
- PackStream v1 and Bolt 5.0–5.8 / 4.4 (handshake proposes 5.8–5.0 and 4.4), chunked messages, HELLO / LOGON, BEGIN / RUN / PULL / COMMIT / ROLLBACK / RESET / ROUTE. Reads are cancel-safe (bytes are buffered, messages cut from the buffer), so a query can be cancelled with `select!`.
- Cancel = send RESET on the connection that runs the query; the server interrupts the query and answers the pending requests (FAILURE / IGNORED), then RESET's SUCCESS; the connection is reusable afterwards. An open result keeps its connection and transaction until it is read to the end, abandoned (RESET) or the session closes.
- `bolt://` goes to one address, `neo4j://` asks the cluster for a routing table (ROUTE) per database, picks readers for READ and the writer for WRITE, and refreshes the table when a server says `NotALeader` / `ForbiddenOnReadOnlyDatabase`. `+s` verifies the certificate (CA file and client certificate come from the connection's TLS settings, through `transport::tls`), `+ssc` accepts a self-signed one. Over an SSH tunnel routing is switched off (the cluster's own addresses are not reachable).
- Element ids are the Bolt 5 `elementId` strings; against a Bolt 4.4 server they are the decimal node id, and the expand / edit queries use `id(n) = toInteger($id)` there.
- Query timeouts use `tx_timeout`, so the server ends the transaction.

### Cypher editor
Neo4j publishes open-source (Apache-2.0) Cypher language support for CodeMirror 6 (the `@neo4j-cypher/*` packages: language support, highlighting, schema-aware completion). Use it, feeding it Clew's schema snapshot and theming it from tokens; verify current package names at implementation time. Fallback: a CM6 StreamLanguage with a keyword list plus Clew's own completion source.
**Decision at implementation (frontend):** the fallback is used. `@neo4j-cypher/codemirror` is unmaintained (last release 2024) and the maintained `@neo4j-cypher/language-support` is only published as 2.0.0-next.* pre-releases of about 130 MB unpacked (ANTLR grammar and runtime, unpinned `antlr4` dependencies), which does not belong in a desktop bundle. `src/features/graph/cypher/` holds a `StreamLanguage` tokenizer (labels and relationship types after `:` in patterns, map keys, `$parameters`, functions) and a completion source fed with the graph schema (labels with counts, relationship types, property keys; functions and procedures from a built-in list unless the schema snapshot carries `functions` / `procedures`). The splitter gains a `cypher` dialect (`//` comments, `--` is a relationship).

### Graph rendering
Cytoscape.js (MIT) with the `fcose` layout extension: canvas rendering, handles thousands of elements, built-in pan/zoom/selection/drag, and a stylesheet API we drive from tokens. Label colors come from a fixed 10-color list derived from token hues, assigned by a stable hash of the label name so the same label always gets the same color across sessions. Captions: user-selectable property per label, stored in `ui_state`. Accessibility: a hidden, focusable list mirrors the graph elements for keyboard and screen readers.
Implementation notes: `cytoscape` 3.34.3 and `cytoscape-fcose` 2.2.0 (pinned). fcose has no worker mode, so the layout runs on the main thread (animated, existing and pinned nodes kept fixed when neighbours are added); the 300-node cap keeps it responsive. Label colours are `LABEL_TOKENS` in `palette.ts`, resolved from the computed token values because a canvas cannot use `var()`.
Alternative considered: d3-force + custom canvas (more work for hit-testing and interactions); vis-network (heavier, less active).

### Results model
`GraphResult { records, nodes: Map<ElementId, Node>, relationships: Map<ElementId, Rel> }` built in Rust while streaming so the frontend gets de-duplicated elements. Expand neighbours runs `MATCH (n)-[r]-(m) WHERE elementId(n) = $id RETURN r, m LIMIT 25` in a READ transaction.
Implementation: commands `graph_query`, `graph_fetch_more`, `graph_expand`, `graph_schema`, `graph_databases`, `graph_update_properties` and `graph_update_safety_check` (`src-tauri/src/commands/graph.rs`); the driver side is the `GraphSession` trait. `nodes` and `relationships` are de-duplicated per batch (the frontend merges batches by element id). A graph cell is a `Value` of kind `node`, `relationship` or `path` (camelCase fields); maps become `json`, lists `array`, points `other` (`point({srid: 4326, x: 1, y: 2})`), durations `interval` (`P1Y2M3DT4H5M6.5S`), and anything unknown `other`. A result stays open on the server (`cursor_id`) until it is read to the end; write queries and PROFILE are read to the end at once so the transaction commits (the first batch is returned and up to 50,000 further rows are buffered for `graph_fetch_more`).

### Safeguards
`safety/classify.rs` gains a Cypher classifier using a lightweight tokenizer (no full Cypher grammar in Rust): it looks for updating clauses outside strings/comments, and maintains an allow-list of read-only procedures (`db.labels`, `db.relationshipTypes`, `db.propertyKeys`, `db.schema.*`, `dbms.components`, `SHOW …`).
Implementation: `safety/cypher.rs`. Words after `.`, `:` or `|` and map keys are names, not clauses (`n.set`, `(n:Order)`, `{create: 1}`). `EXPLAIN` is a read; `CREATE INDEX` / `CONSTRAINT` / `DATABASE`, `DROP`, `ALTER`, `GRANT`… are `ddl`; `DELETE` / `DETACH DELETE` whose statement has no `:` label or type, `{}` property map, `WHERE` or `LIMIT` is dangerous (typed confirmation on production). `:use <db>` is session control. The statements that Neo4j only runs outside an explicit transaction (`CALL {} IN TRANSACTIONS`, `USING PERIODIC COMMIT`, schema and admin commands) are sent in auto-commit mode.

## Risks / Trade-offs

- [The in-house Bolt client misses a protocol corner] → Covered by unit tests of PackStream and the value conversions, and by the integration tests against `neo4j:5` (records, paging, cancel, routing, temporal types, big integers); unknown structures fall back to value kind `other`. Not yet exercised in CI: Neo4j 4.4, a real cluster, TLS (`+s`) and AuraDB.
- [Graph layouts on large results are slow] → Cap at 300 nodes by default, run layout in a Web Worker where the extension allows, and offer Table view.
- [Cypher tokenizer misclassifies exotic queries] → Unknown/ambiguous → treated as write; READ access mode is the backstop on read-only sessions.
