## Context

SQL drivers share one session contract; NoSQL stores need different operations. Canvas: `design/canvas/MongoBrowser.dc.html` (tree grid with Key/Value/Type columns, query bar fields, view switcher, Redis keys in the side list).

## Decisions

- **Family traits.** `DocumentSession` and `KeyValueSession` extend the base session; `DriverMeta.family` selects them. Results reuse `ResultEvent` with a `Documents(Vec<EJson>)` variant so streaming, paging and cancel work the same.
- **Relaxed shell syntax parsing** in Rust (`drivers/mongodb/shell_parse.rs`): a JSON5-like parser extended with `ObjectId`, `ISODate`, `NumberLong`, `NumberDecimal`, `UUID`, regex literals. No JavaScript engine: predictable and safe.
- **Explain for the index label:** after a find, run `explain("queryPlanner")` in the background (cheap) and report the winning plan's index or COLLSCAN.
- **Tree grid** reuses Glide Data Grid with a custom tree column (indent = 20px per depth, caret) so tree, table and grid share selection and copy behaviour.
- **Edits** use `replaceOne({_id, ...originalVersionCheck})` when the whole document is edited, `updateOne` with `$set`/`$unset` for field edits. The version check compares the edited fields' original values.
- **Redis** via `redis` crate `tokio-comp` + `tls-rustls`. SCAN with `COUNT 1000` and `TYPE` per key pipelined; TTL via `PTTL`. Command parsing for the console uses the server's `COMMAND DOCS` (Redis 7) for completion when available.
- **Safeguards** classification is extended: Mongo writes = insert/update/delete/drop/createIndex; Redis writes = commands flagged `write` in `COMMAND INFO`; `FLUSHDB/FLUSHALL/DEL` with patterns are "dangerous".

## Risks / Trade-offs

- [Users expect full mongosh JavaScript] → Explicitly out of scope; the error message explains the supported subset. Revisit with an embedded JS engine later.
- [SRV + SSH tunnel] → SRV resolves to multiple hosts; tunnelling them is unsupported in v1 (dialog disables SSH for SRV URIs).

### Decisions made during implementation

- **Documents travel as canonical Extended JSON.** `ResultEvent::Documents` and every document request/reply carry canonical EJSON (`{"$numberInt":"5"}`, `{"$oid":…}`, `{"$date":{"$numberLong":…}}`), not relaxed: Int32, Int64 and Double stay distinct through the WebView, so an edit keeps (or deliberately changes) a value's type. The tree, table and JSON views turn it into display text (`frontend: features/documents/ejson.ts`); the shell text people type goes the other way through the Rust parser (`DocRequest::Evaluate`), so there is one parser, not two.
- **The Extended JSON requirement says "relaxed".** Display text and exported files use relaxed Extended JSON (`Bson::into_relaxed_extjson`) and the shell's constructors; only the wire format is canonical.
- **Traits are reached through the base `Session`.** `Session::as_documents()` / `as_keyvalue()` return the family interface, so one `SessionManager` and one session map serve every family; `doc_call`, `doc_safety_check` and `kv_call` are the new Tauri commands. `Session::execute` is the console (below), so history, cancel, timeout, paging and export reuse the SQL path.
- **Consoles reuse the SQL console.** A Mongo or Redis console is the existing console with a different language: `execute` runs one shell command / one Redis line and answers in the standard `Columns`/`Rows`/`Done` events (documents flattened to top-level fields, a Redis reply as a small table), plus `Documents` events so Mongo results can also be shown as Tree or JSON. Redis scripts are one command per line (`#` comments); Mongo scripts split at `;`. No Explain and no transaction controls on these consoles.
- **Safeguards classify text.** `safety/nosql.rs` classifies a Mongo command (find/aggregate/count/distinct/getIndexes are reads, `$out`/`$merge` pipelines and insert/update/delete/replace are writes, createIndex/dropIndex/drop are DDL, `deleteMany({})`, `updateMany({})` and `drop()` are dangerous) and a Redis line (an allow-list of read commands, with sub-command rules for `CONFIG GET`, `CLIENT LIST`…; everything else is a write; `FLUSHDB`, `FLUSHALL` and `DEL`/`UNLINK` with a glob are dangerous). The browser's own edits are turned into the equivalent shell text first (`doc_safety_text`), so one guard (read-only, confirm, typed confirmation on production, one-time tokens) covers consoles and browsers. The Redis driver additionally asks the server which commands are flagged `write` (`COMMAND INFO`), as a backstop on read-only sessions.
- **Field-level version check.** An edit sends the original value of every field it touches (`FieldCheck`, with `absent` for fields that did not exist, so `null` and "missing" differ). The write filter is `{_id, field: originalValue…}`; no match means a conflict, and the reply carries the document as it is now (or `null` when it is gone) for Reload / Overwrite. Edits that dotted `$set` paths cannot express (keys containing `.` or starting with `$`, removing an array element) fall back to `replaceOne`, checked against every original top-level field.
- **Counting and the plan run off the critical path.** After a find the first page is shown, then `countDocuments` (capped at 100,000, shown as `100,000+`) and `explain("queryPlanner")` fill the "<n> of <total> matched · <ms> ms · index <name>" line; MongoDB 8's `EXPRESS_IXSCAN` counts as an index.
- **JSON view folds.** The read-only JSON view renders lines with a fold control on every object and array (`foldModel.ts`) rather than embedding a code editor.
- **Redis is tabbed by database, not nested in the tree.** The explorer lists `db0`… (those with keys, plus db0) with their key counts; double-clicking one opens the key browser, whose side list does the incremental `SCAN` (`COUNT 1000`, `TYPE` and `PTTL` pipelined, never `KEYS`), the glob filter and "Load more". Keys are grouped by the part before the first `:`.
- **Redis edits are console lines.** The viewers issue `HSET`, `LSET`, `ZADD`, `SET … KEEPTTL`, `EXPIRE`/`PERSIST`, `RENAMENX`, `DEL`… with quoted arguments through the same guard as the console. Binary values are shown as hex only and are not editable. Strings over 1 MB show their first 1 MB read-only.
- **Console completion is static.** Redis command names come from a bundled list and MongoDB offers collections (from the schema snapshot), the supported methods and cursor modifiers; the `COMMAND DOCS`-based argument completion in the design above is left for later.
- **TLS and tunnelling.** MongoDB uses the `mongodb` crate's rustls support (a CA file and a combined client certificate/key file); the Redis driver uses the OS trust store (a CA file for Redis is not supported yet, `Require` skips verification). SSH works for `mongodb://` URIs by tunnelling to the first host and adding `directConnection=true`; `mongodb+srv://` is refused with an explanation.
- **Deferred.** Redis `COMMAND DOCS` argument hints, a "new key" action in the key browser, cluster mode (detected and refused with "Redis Cluster isn't supported yet"; no cluster in CI to exercise it), and the e2e journey J-14 (tasks 5.1, 5.2) until an `e2e/` framework exists.
